## 装好了然后呢

很多人装好Claude Code之后，打开终端，看着光标闪了两分钟，然后关掉了。

因为不知道该说什么。

这篇文章解决这个问题。我们做一个真实的小工具：**一个每日AI新闻聚合器**，自动从网上抓取AI相关的最新文章，整理成一份格式好看的日报。

选这个项目，是因为它不太大也不太小——一个下午能做完，但涉及网络请求、数据处理、AI调用、文件输出，足够让你把Claude Code的基本流程全走一遍。

在开始之前，先做一个心态切换：

**从现在开始，你是产品经理，Claude是你的工程师。你的活是说清楚要什么，不是写代码。**

哪怕你是资深程序员，也先按这个方式来一遍。

---

## 第一步：告诉Claude你要什么

打开终端，新建一个空文件夹，启动Claude Code：

```bash
mkdir ai-news-digest && cd ai-news-digest
claude
```

然后，用自然语言告诉Claude你想要什么：

```
帮我做一个AI新闻聚合CLI工具。需求如下：

1. 从以下RSS源抓取最近24小时的文章：
   - TechCrunch AI (https://techcrunch.com/category/artificial-intelligence/feed/)
   - The Verge AI (https://www.theverge.com/rss/ai-artificial-intelligence/index.xml)
   - Hacker News AI相关文章 (https://hnrss.org/newest?q=AI&count=30)

2. 对每篇文章提取标题、链接、发布时间、来源

3. 按时间倒序排列，输出一份Markdown格式的日报到output/目录

4. 用TypeScript写，用tsx直接运行

先别急着写代码，给我一个实现方案。
```

注意最后那句"**先别急着写代码，给我一个实现方案**"。这不是客气，是一个很重要的技巧：让Claude先想清楚再动手，能避免很多返工。

---

## 第二步：看它给方案，你来评审

Claude收到需求后，不会直接开写代码，会先给你一个方案。大概是这样的：

```
我来帮你做这个AI新闻聚合工具。先说一下方案：

项目结构：
ai-news-digest/
├── src/
│   ├── index.ts          # 入口文件
│   ├── fetcher.ts        # RSS抓取逻辑
│   ├── formatter.ts      # Markdown格式化
│   └── types.ts          # 类型定义
├── output/               # 日报输出目录
└── package.json

技术方案：
- RSS解析用 rss-parser 库
- 日期处理用 date-fns
- 用tsx直接运行TypeScript，不需要编译步骤

实现流程：
1. 并行抓取三个RSS源
2. 统一格式、过滤24小时内文章
3. 按时间排序
4. 生成Markdown格式日报
5. 写入 output/YYYY-MM-DD.md

需要我开始实现吗？
```

这时候你就是在看技术方案的产品经理。觉得行就说OK，想调整就直接说。

比如你想加点东西：

```
方案没问题。补充两点：
1. 日报里每篇文章加一句话摘要（从description里截取前100字）
2. 日报开头加一个统计：共收录X篇，来自Y个源
```

这个来回，就是对话式编程的核心——Claude出方案，你补充细节，Claude修正。不需要画流程图，不需要写技术文档，直接用人话说。

---

## 第三步：看它干活

确认方案后，Claude开始执行。终端里会出现一系列操作：

**初始化项目**：Claude会自动运行 `npm init -y`，然后安装依赖包。你会看到它请求运行命令的权限提示：

```
Claude wants to run: npm init -y
Allow? (y/n)
```

按 `y` 允许。后面安装依赖包时也会有类似提示，都按 `y` 就好。

**创建源代码文件**：Claude会逐个创建文件。你会看到它写入代码的过程，每个文件都会展示改动内容。不需要逐行看，快速扫一眼文件结构是否合理就行。

**运行测试**：代码写完后，Claude通常会自己试着运行一次。如果报错了，它会自己读错误信息、找问题、改代码、再运行，自动修复循环。

整个过程大约2到5分钟。你干嘛？**看着就行。**

就像把任务交给一个新同事，前几次你会盯着看他怎么做事，熟悉了他的风格之后，以后放心让他自己干就好。

---

## 第四步：看看结果对不对

Claude干完了，跑一下看看：

```bash
npx tsx src/index.ts
```

如果一切顺利，你会在 `output/` 目录下看到一个Markdown文件，内容大概是：

```markdown
# AI新闻日报 — 2026-04-16

> 共收录 18 篇文章，来自 3 个源

---

## TechCrunch AI

### OpenAI发布新版模型，响应速度提升30%
🔗 https://techcrunch.com/...
📅 2026-04-16 14:30
> OpenAI今日发布了新版模型，主要改进集中在推理速度上，比上一版本快约30%...

---
## The Verge AI

### Google宣布AI搜索全面升级
...
```

打开文件看看格式和内容。大多数情况下，第一次就能跑通。

如果报错了，**直接把错误信息粘贴给Claude**：

```
运行报错了：
TypeError: Cannot read properties of undefined (reading 'map')
  at formatArticles (src/formatter.ts:15:23)
```

Claude会读错误信息、定位问题、改代码、再跑。报错到修复，一般1到2轮就搞定。

---

## 第五步：加功能

能跑了，但你想加点东西。继续用自然语言说就行：

```
现在每篇文章的摘要是从description截取的，比较粗糙。
改成用AI来总结：对每篇文章用Claude API生成一句话总结。
API key从环境变量 ANTHROPIC_API_KEY 读取。
```

Claude会修改代码，加入API调用逻辑。你验证后继续：

```
加一个去重逻辑，有些文章在多个源里重复出现了，基于URL去重。
```

每一轮，Claude改代码、跑测试、确认结果。**你始终只做两件事：说清楚要什么，验证结果。**

---

## 一个重要的心态转变

做完这个项目，你应该有个感受：**你的价值不在于写代码，而在于定义要做什么、判断做得对不对。**

很多工程师第一次用Claude Code时，本能地想看每一行代码、理解每个实现细节。正常反应，但这会让你变慢。

更高效的方式是把它当团队成员来管理：

| 传统编程 | Claude Code编程 |
|---------|----------------|
| 自己想方案，自己写代码 | 描述需求，Claude出方案和代码 |
| 一行一行调试 | 把错误信息给Claude，它自己调 |
| 查文档、查StackOverflow | 直接问Claude"怎么实现XXX" |
| 代码review靠人工 | 让Claude解释它写的代码 |

不是说完全不管代码。而是你的注意力应该在更高层面：**需求准不准确？方案合不合理？结果符不符合预期？**

## 新手常见问题

**"代码看不懂怎么办？"**

直接问它。"解释一下 fetcher.ts 的实现逻辑"，Claude会用人话讲清楚。还可以追问细节。你不需要能写出这段代码，但需要理解它在做什么——就像你不用会修发动机，但得知道车在不在正常运转。

**"写错了怎么办？"**

描述现象比定位代码行更有效：
- 推荐说："运行后只输出了TechCrunch的文章，另外两个源的文章没有。检查一下抓取逻辑。"
- 不推荐说："你的代码第23行有bug。"

Claude能看到全部代码，它可能发现问题根源不在你以为的地方。

**"跑偏了怎么办？"**

偏得不远，直接纠正："停，不要用XXX库，换YYY。"

偏得太远，按 `Esc` 停止，重新描述需求。按两次 `Esc` 会打开回滚菜单，可以回滚对话、回滚代码改动，或者两者都回滚。

一个经验：**纠正两次还不行，果断停下来重来**。在错误基础上打补丁只会越补越乱。

---

## 今天你学到了什么

**对话式编程的五步法**：描述需求 → 审查方案 → 确认执行 → 验证结果 → 迭代改进。

不管项目大小，这个模式是通用的。

**你的角色是产品经理**，管要什么和好不好；Claude的角色是工程师，管怎么实现。这个分工形成默契之后，生产力会有质的变化。
