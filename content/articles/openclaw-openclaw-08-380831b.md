## AI 写作最失败的用法：一上来就让它写全文

很多人用 AI 写文章，第一句话就是：

```text
帮我写一篇关于 OpenClaw 的公众号文章。
```

然后得到一篇很完整、很平、很像 AI 的文章。

不是不能用。

但很难有灵魂。

因为内容创作不是只有“写正文”。

真正耗时间的是：

- 找选题
- 判断选题值不值得写
- 查资料
- 核对事实
- 搭结构
- 找类比
- 写开头
- 改标题
- 审稿
- 做发布检查
- 整理素材库

OpenClaw 最适合参与的不是“替你一键写完”，而是：

**把内容生产拆成一条工作流，然后让它接管那些重复、繁琐、可检查的环节。**

---

## 内容工作流的 6 个环节

建议把内容生产拆成这 6 步：

```text
选题雷达
  ↓
资料卡片
  ↓
文章大纲
  ↓
初稿生成 / 人工写作
  ↓
审稿优化
  ↓
发布检查
```

OpenClaw 每一步都能参与，但参与方式不一样。

| 环节 | OpenClaw 最适合做什么 | 人最好做什么 |
|---|---|---|
| 选题 | 收集、归类、打分 | 判断战略方向 |
| 资料 | 摘要、核查、保存卡片 | 判断观点取舍 |
| 大纲 | 搭结构、列案例 | 决定主线 |
| 初稿 | 生成段落、补例子 | 写关键观点 |
| 审稿 | 查漏补缺、去 AI 腔 | 保留个人风格 |
| 发布 | checklist、摘要、配图 brief | 最终发布 |

一句话：

> **让 OpenClaw 做编辑部助理，不要让它直接当总编辑。**

---

## 先搭一个内容工作区

建议在 workspace 里建这些目录：

```text
~/.openclaw/workspace/
  content/
    topics/
    notes/
    outlines/
    drafts/
    reviews/
    publish-checklists/
    assets-briefs/
```

目录职责：

| 目录 | 放什么 |
|---|---|
| `topics/` | 选题池 |
| `notes/` | 资料卡片 |
| `outlines/` | 文章大纲 |
| `drafts/` | 初稿 |
| `reviews/` | 审稿意见 |
| `publish-checklists/` | 发布前检查 |
| `assets-briefs/` | 配图和封面 brief |

不要把文章、资料、草稿全丢一个文件夹。

文件一乱，AI 也会乱。

---

## 第一步：选题雷达

选题雷达适合用 Cron + Standing Order。

在 `AGENTS.md` 里写：

```markdown
## Program: 内容选题雷达

**Authority:** 你被授权收集 AI 工具、Agent、AI 编程、效率工具相关选题线索。
**Trigger:** 每周一上午 9 点，由 cron 触发。
**Approval gate:** 不自动写完整文章，不自动发布。
**Escalation:** 涉及最新产品功能、价格、政策、发布日期时，必须标注来源和核对时间。

### Execution steps
1. 收集最近一周值得关注的 AI 相关话题
2. 筛选普通创作者、职场人、独立开发者真正能用的内容
3. 按“教程价值 / 传播潜力 / 可操作性 / 可信度”打分
4. 生成 10 个选题
5. 每个选题给出标题候选、核心观点、目标读者、文章结构
6. 保存到 content/topics/YYYY-MM-DD-topic-radar.md
7. 给我发送前 5 个推荐选题摘要

### What NOT to do
- 不要制造焦虑
- 不要只追热点没有方法
- 不要把未经核实的爆料当事实
```

Cron 触发：

```bash
openclaw cron create "0 9 * * 1" \
  --name "Content topic radar" \
  --session main \
  --system-event "执行 AGENTS.md 中的 Program: 内容选题雷达。"
```

这会让选题从“灵感来了再写”变成“每周稳定补货”。

## 第二步：资料卡片

当你看到一篇文章、一个产品文档、一个视频脚本，可以发给 OpenClaw：

```markdown
请把这份资料整理成内容卡片。

要求保存到 content/notes/日期-主题.md。

卡片结构：
1. 来源链接
2. 核心结论
3. 关键事实
4. 可以引用的数据
5. 需要核实的信息
6. 适合写成公众号的角度
7. 可用类比
8. 配图建议

不要照搬原文表达。
不确定的信息标注“待核实”。
```

这一步非常重要。

因为你不是在“收藏链接”。

你是在把外部资料变成自己的素材库。

一个好的内容创作者，不是记忆力强，而是素材系统强。

---

## 第三步：大纲生成

大纲不要让 AI 自由发挥。

你要给它主线。

示例：

```markdown
请基于 content/notes/openclaw-channel.md 生成一篇公众号文章大纲。

主题：OpenClaw 手机通道怎么选
目标读者：已经跑通 Dashboard，想接 Telegram 或 WhatsApp 的新手
核心观点：不要一上来全渠道，先选一个入口跑稳

大纲要求：
1. 开头用一个具体误区
2. 先解释通道在 OpenClaw 中的位置
3. 对比 Telegram、WhatsApp、WebChat
4. 给出推荐路线
5. 加入安全提醒
6. 结尾预告下一篇

输出：
- 标题候选 10 个
- 推荐标题 1 个
- 文章大纲
- 每节核心论点
- 配图建议
```

注意这里的关键：

你给了目标读者、核心观点、结构要求。

AI 就不是乱写，而是在帮你搭架子。

---

## 第四步：初稿生成，不要整篇盲写

初稿可以让 OpenClaw 写，但建议分段写。

比如：

```markdown
请先只写开头部分，800 字以内。

要求：
1. 从“很多人一跑通就想全渠道接入”这个误区切入
2. 语气口语化但专业
3. 不要写宏大背景
4. 3 段内进入主题
5. 给出一句加粗核心判断
```

写完你确认开头主线，再写下一节。

不要一次让它写 5000 字。

长文最怕主线偏。

分段写，你还能控方向。

如果你自己写正文，也可以让它做“伴写”：

```markdown
我会自己写这一节。
请你只帮我提供：
1. 3 个生活类比
2. 2 个真实使用场景
3. 可能的误区
4. 这一节适合的配图建议
不要直接写正文。
```

这比“替我写”更高级。

---

## 第五步：审稿，用 Skill 固定标准

第 7 篇我们做了 `wechat-article-review` Skill。

现在就能用：

```markdown
用 wechat-article-review 检查 content/drafts/openclaw-channel.md。

重点检查：
1. 开头是否太慢
2. 有没有 AI 腔
3. 是否有事实风险
4. 是否缺少配图建议
5. 哪些段落可以删

不要直接改正文，先给审稿意见。
```

为什么先不给它改？

因为审稿和改稿是两件事。

先看问题，再决定怎么改。

如果你直接让它改，它可能把你的风格也改没了。

---

## 第六步：发布检查

发布前，OpenClaw 很适合做 checklist。

```markdown
请对这篇文章做发布前检查。

检查项：
1. 标题是否清楚
2. 摘要是否适合公众号
3. 是否有错别字
4. 命令和链接是否需要核对
5. 是否有配图建议
6. 是否有下一篇预告
7. 是否有明显 AI 腔
8. 是否有可能误导读者的表达

输出：
- 是否建议发布
- 必改问题
- 可选优化
- 公众号摘要
- 封面图 brief
- 朋友圈转发文案
```

这一步很适合自动化成 Skill。

但发布动作本身，建议人工完成。

**让 AI 做发布前检查，不要让 AI 替你按发布按钮。**

## 内容工作流里的 3 个 Standing Orders

### 1. 每周选题雷达

前面写过。

每周产出选题池。

### 2. 每日素材整理

```markdown
## Program: 每日素材整理

**Authority:** 整理我当天发给你的链接、截图、文件和想法。
**Trigger:** 每天晚上 22 点。
**Approval gate:** 不自动写完整文章。
**Escalation:** 如果素材来源不可靠，标注待核实。

### Execution steps
1. 汇总当天我发过的内容素材
2. 按主题归类
3. 生成 3-5 张资料卡片
4. 保存到 content/notes/YYYY-MM-DD-materials.md
5. 给我一个明天可写选题建议
```

### 3. 发布前审稿

```markdown
## Program: 发布前审稿

**Authority:** 对我指定的文章进行质量检查。
**Trigger:** 当我说“发布前检查”时。
**Approval gate:** 不直接发布，不直接重写全文。
**Escalation:** 发现事实风险、命令风险、版权风险时必须置顶提醒。
```

这三个 Standing Orders 覆盖了：

```text
写前
写中
写后
```

内容创作就稳多了。

## 给 OpenClaw 的内容创作总模板

你可以保存到 `content/templates/article-task.md`：

```markdown
# 文章任务模板

## 主题

## 目标读者

## 核心观点

## 资料来源

## 文章类型
- 教程
- 科普
- 观点
- 工具测评
- 实战复盘

## 输出要求
1. 标题候选
2. 文章大纲
3. 正文草稿
4. 配图建议
5. 事实核查清单
6. 发布前 checklist

## 风格要求
- 中文
- 口语化但专业
- 抽象概念配类比
- 不要虚构事实
- 不要营销腔
```

以后每篇文章都从这个模板开始。

这比临时聊天稳定得多。

## 内容创作者最容易踩的 6 个坑

### 坑 1：直接让它写全文

结果文章完整但平。

解决：拆成选题、资料、大纲、分段、审稿。

### 坑 2：不核对最新信息

AI 工具变化太快。

涉及功能、价格、命令、发布时间，必须查官方资料。

### 坑 3：把 AI 的话当观点

AI 可以帮你整理，但观点要你定。

### 坑 4：风格被改没

审稿时先让它提问题，不要直接改全文。

### 坑 5：素材不沉淀

每天问，每天忘。

解决：资料卡片保存到 `content/notes`。

### 坑 6：发布动作自动化

新手不要让 AI 自动发布。

先人工确认。

## 今天的核心

OpenClaw 用在内容创作里，最好的定位不是“AI 写手”。

而是：

**选题助理、资料助理、结构助理、审稿助理、发布检查助理。**

真正稳定的内容工作流是：

```text
选题雷达
  ↓
资料卡片
  ↓
大纲结构
  ↓
分段写作
  ↓
Skill 审稿
  ↓
发布检查
```

你负责判断、观点和最终表达。

OpenClaw 负责把重复、繁琐、可检查的部分系统化。
